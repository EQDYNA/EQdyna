# Session notes: user docs site (board row 126)

Checkpoint log for the MkDocs Material user-docs-site mission (haruto-nakamura,
worktree `agent-ad1afebbdb7e66ef3`, branch `docs/user-site`).

## What landed

* `docs/user/mkdocs.yml` -- MkDocs Material config, `docs_dir: .` (so the
  source is `docs/user/` itself, keeping the repo root clean per rule 1a),
  `site_dir: ../user-site` (must be outside `docs_dir`; gitignored).
* `docs/user/requirements.txt` -- pinned `mkdocs==1.6.1`,
  `mkdocs-material==9.5.49`.
* New pages: `index.md`, `getting-started.md`, `running-a-case.md`,
  `outputs.md`, `citing.md`.
* Updated pages: `benchmarks.md` (added an example plot, copied from
  `case_input/test.tpv8/cRuptureDynamics.png` into
  `docs/user/assets/benchmarks/`, and switched the per-case README links
  to absolute GitHub URLs -- a relative link to a `.md` file outside
  `docs_dir` fails `mkdocs build --strict`).
* `docs/user/parameters.md` -- new page, its parameter-reference section
  generated by `docs/user/gen_params.py` from
  `scripts/defaultParameters.py`'s `parameters` class (114 entries, 7
  section headings as of this session). The generator filters any single
  comment line, or drops a whole comment block, that trips the same
  internal-reference markers `test_user_docs_style.py` refuses (rule 26) --
  printed at generation time, never silently dropped. 4 blocks were dropped
  this run (`viscoplasticRelaxTime`, `devStrTaperDepthStart`,
  `plasticOutputHalfWidth`, `faultStNormalStressSign` each cite an internal
  file or board reference in their source comment).
* `testsys/regression/test_params_reference_freshness.py` -- staleness
  guard, same BEGIN/END-marker contract as
  `test_stop_exit_status.py`'s exit-code table. Mutation-checked: editing
  the committed page without regenerating goes red; regenerating clears it.
* `testsys/regression/test_user_docs_commands.py` -- extends
  `test_readme_commands.py`'s command-resolution checks to every
  `docs/user/**/*.md` page. Reuses that file's check functions
  (parameterized by `text`/`label`, not copied) rather than a second
  implementation.
* `testsys/regression/test_readme_commands.py` -- parameterized its five
  check functions (`text=None, label='README.md'`) so
  `test_user_docs_commands.py` can call them against a different document;
  `check_optin_env_vars_are_documented` additionally skips a page that never
  invokes the gated script at all (otherwise every page that doesn't
  mention `e2e-full` would fail trivially).
* `.github/workflows/docs.yml` -- new workflow. `pull_request` (paths
  `docs/user/**`, this file): build only, `mkdocs build --strict`.
  `push` tag `v*`: build, then a separate `deploy` job using
  `actions/configure-pages`, `actions/upload-pages-artifact`,
  `actions/deploy-pages`, with `permissions: pages: write, id-token:
  write`. Does not touch `.github/workflows/test.yml` (a pending branch
  owns it) and does not conflict with `.github/workflows/publish.yml`
  (same `push: tags: v*` trigger, different job names, different
  destination -- GHCR vs GitHub Pages -- and disjoint permissions).
* `testsys/ci_shard.py` -- registered both new regression scripts (shard 2).
* `.gitignore` -- added `docs/user-site/` (the mkdocs build output).
