Record of tasks done and open issues for this repo. See `PROJECT_RULES.md` for
the rules each item enforces. History (what shipped, when) lives in
`pastReleaseNotes.md` and `README.md` -- this file does not duplicate it and is

**Restructured 2026-09-23.** The board was 440,433 bytes over 394 lines at
`2e1624d` -- median table row 1,006 bytes, longest row **32,331 bytes** (item
33) -- because multi-session investigation narratives were living inside a
status table, and because the same item could hold a row in each of two
different tables (8 items did). There is now ONE table shape and four
sections, read in this order:

| section | what is in it | what a reader does |
|---|---|---|
| **A. Open work** | something to do, P1 first | pick the top row whose prerequisite is met |
| **B. Blocked on owner** | measured or built as far as it can go; needs a ruling | do not start these; answer the `blocked on` cell |
| **C. Records and standing state** | measurements already taken, decisions already made, assets to watch | read, cite, do not re-dispatch |
| **D. Closed** | outcome, SHA, date, evidence command -- one or two sentences | check a claim, then stop |

The investigation narrative behind the rows lives in `docs/BOARD_HISTORY.md`,
verbatim and unedited. It was **relocated, not deleted**, and every row that
had one points at it. That archive carries no priorities and no open items: an
obligation found there that no row here carries is a defect in this file.

A blank "Last checked" means never audited and stays blank until someone
actually runs the command. **A row's `Command` must be able to come out BOTH
ways** (rule 14a) -- a command that can only pass is not evidence, and two rows
were once found carrying commands that could never go red.

**Nine columns, fixed:** `rank | item | what | status / why this rank | rules |
surface | blocked on / re-check | last checked | command`. A row with fewer
cells than that silently drops the ones past the header's width, which is how
an unrunnable command hid in plain sight until 2026-09-21 -- pad short rows
with empty cells rather than omitting them, and escape any literal `|` inside a
cell as `\|` (an unescaped one starts a new column mid-sentence; four rows in
the pre-refactor file were doing exactly that).

a mechanical contention/box-state field in the ledger would have to be defined
first, and that is item 76, owner-scoped.
